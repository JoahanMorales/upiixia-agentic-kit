## UAK-192 · The wizard runs the command for you: a button where today it shows a command to copy

- **Type:** feature
- **Priority:** P0
- **Estimate:** 8 h
- **Depends on:** UAK-159
- **Paths:** kit/.uak/bin/lib/setup.html, kit/.uak/bin/lib/setup.py, kit/.uak/bin/lib/workspace.js, kit/.uak/docs/SECURITY.md, kit/.uak/docs/CLI.md, kit/.uak/tests/test_setup_run_here.py, kit/.uak/tests/test_setup_language.py, kit/.uak/tests/timings/test_setup_run_here.txt
- **Acceptance:**
  - every command the wizard shows in a copy box has a button that does it from the page, and the copy box stays beside it for who prefers the terminal. Why (the human, 2026-11-24, on the screens of UAK-159): "if it is meant to make the work easier, why does it make you run commands in an uncomfortable way? can't there be a button to run it from there?"
  - "Start this agent" (the Start screen) opens a terminal window of the person's system in the project folder with the agent's command already running: Terminal on macOS, Windows Terminal or `cmd` on Windows, the first of `x-terminal-emulator`, `gnome-terminal`, `konsole`, `xterm` on Linux. The coding tool is interactive, so it runs in that window, never hidden inside the server. When no terminal can be opened (a remote machine, no display, WSL without one) the button says so in one sentence and the copy box is what remains; the page never says "started" for a window it could not open
  - the commands that are not interactive run in the server and show their progress next to the button, with the time, the last lines of output under "Technical details", and the result in a sentence: deploy help and the smoke that boots the app, adding an external skill, saving the live link, the readiness check, and the command the Rules screen gives to open `PROJECT.md` (it opens the file in the system's editor)
  - the server runs only commands from a fixed list built by the server from the project's state; the page sends the name of an action and its fields, never a command line, and a field is validated like the forms of today (no shell, arguments as a list). A request with an unknown action or a command line is refused and written in the register
  - what the browser may not grant stays that way: the button never writes `Review-Mode`, `Review-Independence`, `Auto-Merge` or `Merge-Engine`, never approves a plan or registers a reviewer in a way the forms of today do not, and never runs with `UAK_HUMAN` set from the page. SECURITY.md lists which actions have a button, which open a terminal, and which stay copy-only with the reason
  - every process a button starts is in `uak-wizard.children` and ends with the wizard like the others (UAK-156), except the terminal windows, which are the person's: closing the wizard leaves them open, and the page says so
  - a running action can be stopped from the page; two clicks do not start it twice; an action that fails says what to do next to its button (the rule of UAK-159)
  - Spanish and English for every new sentence; screenshots at 1280 and 390, light and dark, of the Start screen with one agent started and of one action running, one failed and one refused are in `.uak-shots/UAK-192/`
