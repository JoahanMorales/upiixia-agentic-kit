- **Type:** docs
- **Priority:** P0
- **Estimate:** 6 h

- **Paths:** README.md, llms.txt, docs/GUIDE.md, docs/REFERENCE.md, docs/EVIDENCE.md, docs/media/, scripts/make_media.py, kit/.uak/tests/test_readme.py, kit/.uak/tests/timings/test_readme.txt
- **Acceptance:**
  - the README is rewritten from an empty page, not edited, following what the guides for open-source READMEs agree on (the pull request names the guides read, for example "Art of README", awesome-readme and GitHub's own guidance, and which structure it took from them): at most 300 lines; at the very top the banner image, the title, one line that says the kit's vision, and the badges it had (tests, licence, runtime dependencies, coding tools, M8ven); then the first screen answers what this is (one sentence a person outside the project understands), who it is for, what you get after ten minutes, and the one command to start. Why: the human, 2026-11-25: "every time it fills with more slop and buzzwords and it is not understandable for an agent" (656 lines, 26 top-level sections, a section appended per release); and on the first rewrite of 105 lines the same day: "too short, lifeless, it does not help; as you defined the kit I would not feel like using it"
  - it has a voice and it does not lie: the README may say what the kit is for and where it is going (its vision: several people and their coding agents working on one repository in parallel without stepping on each other; "no chaos" as the aim) in sentences that are marked as aim, and it says what works today in sentences that are true today; what it avoids is the empty word, not the conviction: no superlative with nothing behind it, no "blazing", "seamless", "supercharge", "next-level", "game-changing" or the like (the list lives in the test), and no claim about today that the code does not back. Every number names what was measured and links to where (`docs/EVIDENCE.md`, a run, a task); a number that cannot be traced is removed, not softened
  - it says what the kit has won, with proof: the four events the team won with it (OpenAI x Kavak, Chilangatón, HackADA, Diablos Rojos), each with the event's name and date, the place obtained, the public repository of the entry when it is public, the kit version it ran, and the source of the claim (the CHANGELOG entry, the event's page, or the human's own statement dated in `docs/EVIDENCE.md` when no public record exists); a win with no source in one of those three forms is not printed
  - "How it compares" is back and checked again: a table of the kit beside the tools a reader would otherwise pick, each cell a fact that can be read today in that tool's own public documentation or repository, with the link and the date it was checked; where the other tool is better it says so; a cell that cannot be verified is left out, and the test fails on a row without a source and a date
  - the banner at the top is redrawn in the kit's direction and carries no figure without a source (the old one said "No chaos", "~2 s" and "144×"); the vision line may live in it
  - an agent can act from it: the commands are in code blocks that can be pasted as they are; every `uak` command the README names exists in `kit/.uak/bin/lib/commands.tsv` with the options shown (a case checks each one); a short section "For an agent reading this" says which file to read for what (`AGENTS.md` for the rules, `kit/.uak/docs/CLI.md` for commands, `kit/.uak/docs/WHY.md` for the reasons), and `llms.txt` says the same things in the same order, shorter, with no claim the README does not make
  - what leaves the README is not lost: the walkthroughs go to `docs/GUIDE.md`, the lists of commands, modes, stacks and options to `docs/REFERENCE.md`, the measurements and the team runs to `docs/EVIDENCE.md`; each is linked once from the README, and a case fails when a section of today's README has no home in one of the four files (by its heading or an explicit "dropped: reason" line in the pull request)
  - the screenshots in the README are the product of today (the wizard of UAK-159 and UAK-192, the dashboard of UAK-162, UAK-165 and UAK-198) and each has alt text that says what it shows
  - the existing cases that read the README (`test_tutorial_video`, `test_external_skills`, `test_tokens_elsewhere`, `test_setup_prepare`, `test_merge_engine_policy`, `test_ci_tiers`, `test_ci_shards`, `test_hook_session_start_speed`) keep passing unchanged: what they assert stays in the README or the task stops and lists the lines for the human's `uak allow`
  - the draft is shown to the human before review, as a rendered page and as plain text, in Spanish summary of each section's purpose; the README itself stays in English
