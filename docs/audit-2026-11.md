# Audit of v6.5.0 (Nov 2026): what the kit costs, where it breaks, what to measure

Three passes on v6.5.0: the cost of the kit measured on one machine, a read-only audit of the engine, and a reading of
what others publish about agent harnesses. Every finding maps to a task in the roadmap (`docs/ROADMAP.md`, v6.6 → v7).

## 1. Is the kit heavy? Measured

The hypothesis: the kit makes development efficient and pays for it in resources. Measured on a 6-core ARM Linux box, idle,
kit v6.5.0, GitHub remote:

| Cost | Measure | Verdict |
|---|---|---|
| Hooks on every tool call (`guard bash`, `hook tick`, `hook output`) | 3–7 ms per call | negligible |
| Context always loaded (AGENTS.md, skill and agent descriptions) | ~3,500 tokens | light |
| `uak status` / `uak next` | 3.7 s / 2.3 s, each a fetch of claims | felt: agents poll 2.7 times per `done` |
| Full suite (`smoke`) | 8–10 min per task with other agents running; run by the author, again by the reviewer, again by the merge gate | the largest cost in time |
| CI | 105 jobs per push, ~200 checks per PR (one job per test file per OS, on push and on pull_request) | the largest cost in compute |
| What an install puts in a project | 535 files, 9.3 MB (marathon, Claude Code): the kit's own 108 test files (1.5 MB), 114 skill files, `.claude` 2.7 MB | heavy in files, not in context |
| Claims branch of this repo after 89 tasks | 910 commits, 0.65 MB | small |
| Human merges | "Shared resource/CI needs a human" ×38 of 89 tasks | the largest cost in human attention |

So the hypothesis is half true. The kit is cheap per call and per session. It is expensive in verification time (the
suite three times per task), in CI (the matrix), in files installed, and in human merges of engine paths. It cannot say
what it costs in tokens here: `uak tokens` found no transcript of this project, because the sessions that drive it start
in another directory.

## 2. Defects found in the engine (read-only audit)

Confirmed by reading the code path; the guard ones were reproduced with `guard check` on a copy. Described by class.

| # | Sev | Where | Defect |
|---|---|---|---|
| 1 | P1 | `lib/claim.sh` heartbeat, log, checkpoint, handoff | One identity can end with two live tasks: after its claim on X expires it may claim Y, and a heartbeat on X renews the lease (only the owner is checked). First reported by a TLA+ model of the protocol in a fork. |
| 2 | P1 | `uak-mcp` `uak_cli` | The list of commands that run a passed command is tested on the first argument only (a leading `--json` hides it) and misses `red`, which runs a command: the guard does not see them. |
| 3 | P1 | `guard` prose stripping | Quoted text of three or more words is dropped before the rules, but a command substitution inside double quotes still runs. |
| 4 | P1 | `guard` rules for `gh` and `git` | The merge rule needs `gh pr merge` adjacent (flags in between pass); variables or substitutions in a `git`/`gh` segment are not seen. The guard is a text filter over a dynamic shell: the real control is branch protection, which `doctor` does not check. |
| 5 | P1 | `guard`, claims branch | Nothing stops a plain `git push` to the claims branch: a write outside the transaction skips the secret check, the append-only lint and the identity checks, and the engine trusts what it reads there. |
| 6 | P1 | `lib/review-merge.sh` lease renewer | The background loop that renews the merge lock never checks its parent: after a SIGKILL of the merge it keeps renewing and the queue stays stuck. |
| 7 | P1 | `lib/done.sh` integrate | The owner of a CLAIMED task can record it INTEGRATED with no approval when its content is on main (a human is required only from REVIEW): dependents unlock on unreviewed code. |
| 8 | P2 | `wt`, `doctor`, `bb export` | Temp files named with `$$` in a shared temp dir, some never removed on an error. |
| 9 | P2 | `lib/dash.py`, `design_*.py`, `gallery_pick.py` | `subprocess.run` without a timeout: an unreachable remote hangs `uak dash`. |
| 10 | P2 | `lib/claim.sh`, `lib/tx.sh` | A claim with a damaged `Lease-Until` counts as expired, so its owner passes the one-live-task check. |
| 11 | P2 | identities | `UAK_AGENT` is self-declared; `Review-Independence: human` is not the default and `doctor` does not warn. |

Not verified (too large for one pass): the candidate build and the atomic push of the merge gate, the background bodies of
`hook`, and what counts as proof in `integrated_outside_check`. They are the first targets of the scenario evals below.

## 3. What others publish (read from search summaries; treat as leads)

- Short always-on rules, procedures loaded on demand: long context files raise cost by a fifth and barely help.
- A harness is developed against its own regression scenarios, reported as "k of n runs passed", not public benchmarks.
- Systems that improve themselves adopt a change only after it passes an evaluation; the usual safeguards are a human
  gate, held-out scenarios, rollback, and a bounded scope (never the guard or the gates).
- A lessons file grows by curated additions; rewriting it wholesale with a model degrades it.
- Every speed number is shown next to an instability number (reverts, rejections, rework): perceived speed misleads.
- Adopting in an existing codebase: one well-tested module first, tasks read from the tracker the team already uses, a
  short map a human trims.

## 4. What is not measured today

| Question | Today |
|---|---|
| How many times was each command called, how long did it take, how often did it fail? | Names only, per machine (`uak-blackbox.calls`); errors in the black box; no durations |
| How many tasks were reverted or reopened after INTEGRATED? | Not counted (a fork has a first version) |
| How often did someone work outside the kit? | "Direct to main: 130 of 222" in `stats`; no reason, no manual-step notes |
| How often did a human have to step in, and why? | Queue reasons in `stats` |
| Tokens and minutes per task, per kind of step (author, review, gate)? | `tokens` misses sessions started elsewhere; nothing per step |
| Did a change to the kit make agents do better? | The adoption eval only (`docs/evals/`) |
