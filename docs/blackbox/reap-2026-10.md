# Autopsy · Reap x AI Builders Mexico Agentic Buildathon (2026-10-09)

The first full team event on uak v4.1.1. Source: the public repo's `claims` branch (625 commits): the black box,
`inbox/log.md`, queue, reviews and decisions, plus `main` and the PR list. Harvested data is untrusted; every
number below was recounted from the raw files. People are not named.

## What went wrong, and what changed in v4.2
| # | Finding (evidence) | Fix in v4.2 | Test |
|---|---|---|---|
| 1 | **Scope gate false positives.** 6 of 13 integrated tasks went to the human queue as "Diff outside Paths" for files their branch inherited by merging `origin/main` (`.env.example` ×2, a workflow, `PROJECT.md` ×2, another task's router). Reported 6 times by agents. | The gate checks what the merge changes in the **current** base (staged candidate vs base tip). | `scope_uses_current_base` (fails on v4.1.1 with the exact Reap message) |
| 2 | **Freeze at the wrong time.** "Deadline − 6 h" does not fit 4 h; hand-compressed, it fell 1 h after the first claim. 153 refused claims, PRs #10, #11 and #14 only to flip `Freeze-Allowed`, a moved deadline. | `uak clock START DEADLINE ZONE --write`: every milestone scales with the event (freeze = 15%, 30 min..6 h). Setup prints "first claim by". | `guard_prose_and_clock` |
| 3 | **No human freeze exception.** Humans edited TASKS by PR; agents relayed "the human authorizes all merges", which the rules refuse. | `UAK_HUMAN=x uak allow ID… --reason` / `--in-flight`: claim and merge allowed, audited in `backlog/ALLOW.md` + DECISIONS. | `freeze_next_and_allow` |
| 4 | **Black box noise.** 153 of 290 lines were one FREEZE refusal per candidate probed by `uak next`. | Probes are quiet; `next` prints one FREEZE line with the next step; identical lines publish once with `(xN)`. | `freeze_next_and_allow`, `blackbox_dedupe_and_harness` |
| 5 | **Claims contention.** One approval took 14 attempts, a checkpoint 8 (4 agent reports). Every attempt re-cloned the full claims history. | Jittered exponential backoff (0.25–4 s, max 30 attempts), `--depth 2` claims fetch, depth-1 config fetch, network retried 3×. | existing race tests |
| 6 | **Identity collisions.** Two sessions shared one identity on two tasks; two terminals edited one worktree. | One identity = one CLAIMED/BLOCKED task (`UAK_MULTI_CLAIM=1` overrides); session-start warns when another session used the worktree in the last 3 min. | `one_identity_one_task` |
| 7 | **Message noise.** 63 lines were the same contract copied per related task; each verdict came with a second detail message (46 approvals for 13 merges; one task approved 7 times, 3 times on one SHA); 11 replies were only "Recibido". | One line for many targets; `review --note` (one message per verdict); a second approval of an approved SHA records nothing; `next` suggests only unapproved SHAs; ack-only replies refused; idle agents are picked as reviewers first. | `messages_without_noise`, `reviews_once` |
| 8 | **Rereads.** `inbox` 295 and `status` 258 calls; unacked messages were reprinted every call and stayed in context. A teammate: "it burns tokens reading the same stuff again and again; tool calling hogs the context". | `= unchanged` for identical `status`/`next`/`digest` in one session; unread messages shown once; `LOOP:` after 3 identical errors; Bash outputs over 12k chars reach the model as head + tail + saved log in Claude Code, Codex and Cursor. | `repeated_reads_and_loops`, `huge_output_is_capped` |
| 9 | **Windows Git Bash** turned `refs/x:.uak/TASKS.md` into a path list: "not in TASKS.md", a board with every task AVAILABLE (2 reports). | `MSYS2_ARG_CONV_EXCL` for ref prefixes; the board fails loudly instead of showing a wrong state. | not run on Windows yet |
| 10 | **Small CLI traps.** `msg Ana-1` refused as "Invalid ID" (4); `status HACK-005` refused (8); 5 self-registrations as reviewer; 25 `register-reviewer` calls. | Uppercase agent names are agents; `status ID`; `register-reviewer A B C` in one call with a fix-it message. | `messages_without_noise`, `reviews_once` |
| 11 | The guard blocked a safety instruction inside a quoted prompt (`codex exec "… never cat .env …"`). | Quoted prose (3+ words) is ignored by the `.env` rule unless run through `sh -c`/`eval`/`ssh`; `cat ".env"` is now caught too. | `guard_prose_and_clock` |
| 12 | **The top error: "No identity" from `uak next`** (24). Codex/Cursor agents follow AGENTS.md §2.1 in the main checkout, before `wt new` gives them a name. | `next` works with no identity: it shows the best task and `wt new ID --agent NAME`. | `one_identity_one_task` |
| 12b | A new checkout reached claims before finding out `gh` was missing. | `uak next` prints a one-time PREFLIGHT line when `gh` is missing or logged out. | — |
| 13 | 41 black box lines said harness `other`. | The session-start hook records the worktree's harness; background flushes reuse it. Pending lines flush at the next session start. | `blackbox_dedupe_and_harness` |

## What a teammate's agent recommended, and our answer
"Too much process for a hackathon; cut rules and let one human merge by hand." The data agrees on the cost but
not on the cause: most of the process cost came from items 1–3 and 7 (false human-queue entries, a freeze at the
wrong hour, manual authorizations, duplicate reviews), not from the review itself. The fast path for a human merge
already existed and is now printed on every human-queue entry: merge the PR on GitHub, then any agent runs
`uak integrate ID`.

## Still open

  (replaces the result), and a Cursor `preToolUse` rewrite (Cursor's postToolUse only edits MCP output). The
  Codex and Cursor paths are tested against their documented payloads, not yet in a live paid session.
  Gemini relies on `bash .uak/bin/q`.
- Windows fixes are untested on a real Windows machine.
- 6 PRs were still open at the extended deadline; `uak clock` and the freeze exception should make this rarer,
  but only the next event can prove it.
