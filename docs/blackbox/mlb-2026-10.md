# Autopsy · MLB analytics hackathon, first 60 h (2026-10-12 → 10-15)

The second team event on the kit, and the first on **uak v4.2.1**: a 10-day university sports-analytics
hackathon run in sprint mode. Source: the private team repo's `claims` branch (647 commits): the black box,
`inbox/log.md`, `DECISIONS.md`, reviews, queue and task records, plus `main`. The event was still running at
the time of the autopsy (deadline 10-22). The data is confidential, so this page holds counts only, with no
names, data or results. Every number was recounted from the raw files.

## What it validated
The engine worked across Claude Code, Codex and Cursor on Windows for 60 hours. 32 tasks were integrated with
per-SHA reviews and 12 rejects caught real bugs: per-pitch physics, overclaimed findings, numbers in docs that
did not match the CSVs. The v4.2 fixes held: no "outside Paths" entry came from files inherited from main, `clock` set the freeze,
the review lock turned away a second reviewer, and contracts to many tasks went out as one line. What went wrong
was waiting, Windows gaps and leftover identities.

## What went wrong, and what changed in v4.3
| # | Finding (evidence) | Fix in v4.3 | Test (`test_v43.py`) |
|---|---|---|---|
| 1 | **Approved tasks waited for their owner.** Only the owner could `uak merge`; owners were asleep or in another task. 9 tasks waited 7–13 h after approval; two agents sent the humans "stop delaying and merge" messages. | After `Merge-Adopt-Seconds` (20 min), any eligible agent merges an approved task; `next` points idle agents at it; `Merged-By` is recorded. The lease no longer matters in REVIEW. | `approval_survives_main_merges_and_anyone_merges` |
| 2 | **A clean merge of main voided the approval.** "Update branch" made the SHA stale; re-reviews of pure merges were requested by message and `integrate` refused a merged PR. | The approval carries over when every later commit is a clean 2-parent merge of the base, verified by recomputing the merge tree (`merge-tree`, or a 3-way index merge on git < 2.38). A hand edit still needs a review, and the reviewer is told what moved. | same · `moved_head_is_explained` |
| 3 | **The merge gate had no Python.** The gate's fresh clone has no `.venv`: 6 of 17 human-queue entries were "Smoke red", and agents prepended `<main>/.venv/Scripts` by hand. A Codex agent: "merge smoke failed without exposing the diagnostic log". | The gate puts the worktree's or main checkout's `.venv` (`Scripts` or `bin`) first on PATH, exports `UAK_MAIN_CHECKOUT`, keeps the failed log and quotes its error line in the reason. | `merge_gate_finds_venv_and_explains_scope` |
| 4 | **Scope reasons misled.** All 6 "Diff outside Paths" said "add the dir to Additive-Paths", including for two empty `__init__.py`, the kit's own smoke provenance file and real edits of another task's file. | New empty files are allowed; the provenance file is a shared resource; new vs edited files get different reasons, naming the task that owns the path and the `git checkout origin/main -- PATH` fix. | same |
| 5 | **Ghost identities.** 5 identities were opened for a few minutes and abandoned. Three of one human's got 15 of 44 rotation reviews, and that human told every agent by message they "no longer exist". One review went to the author's own human. | `uak retire NAME` (rotation, messages and approvals skip it; a new claim brings it back). Rotation prefers whoever rejected the previous SHA, then another human's agent, then idle agents. | `rotation_skips_ghosts_and_asks_the_rejecter` |
| 6 | **A re-review cost 3 messages.** Rotation, a "re-review X" note, then "ready" to the rejecter, about 9 times. One integration also wrote one line per dependent owner. | `done --to NAME --note "what changed"` is one message, and the rejecter is asked by default. Integrated notices are one line. | same |
| 7 | **Follow-ups went around the kit.** 3 PRs on integrated tasks were refused by `uak review`; one was approved only by message. | `uak followup ID --title TEXT`: a new task on the same Paths, after ID (Plan-Channel claims, no human needed, no scope change). | `small_cli_fixes` |
| 8 | **Recovery noise.** 22 of 62 DECISIONS lines were lease-recovery receipts, 19 of them for tasks waiting in REVIEW overnight. | REVIEW leases write no recovery. | `small_cli_fixes` |
| 9 | **No output cap on Windows Cursor; Codex's cap hurt.** `hook wrap` skipped Git Bash, so 4 of 4 laptops never got the Cursor cap. Codex's PostToolUse `block` cut documentation reads and "interrupted the tool batch". A Cursor reviewer "could not read the diff". | One rewrite for both: the command goes base64 to `cap --b64`, which PowerShell and bash read alike. On Windows Cursor it only wraps commands both shells read the same way. Codex moved to PreToolUse `allow` + `updatedInput` (no block) with the same allowlist, so reads are never cut. Huge diffs become a per-file index with line ranges. | `output_cap_everywhere` |
| 10 | **No dedupe on Windows.** `= unchanged` never fired: Git Bash has no `ps -o`, so the session key was empty. | Falls back to the session id the session-start hook writes. | `dedupe_without_ps` |
| 11 | **`git init failed.` ×6 on Cursor/Windows** made `status` and `next` exit with an error, cause unknown (the repo lived in OneDrive). | The deadline reconcile is housekeeping: if it fails, `status`/`next` answer from a plain read with a NOTE. `git init` retries 3× and shows its real error. `doctor` warns about synced folders. | `small_cli_fixes` |
| 12 | **CLI traps.** `status --help` was an error; 4 bare "Invalid ID."; 16 "No identity", mostly from the main checkout where agents share one git config; 4 "no active claim" conflicts (heartbeats and commands on finished tasks) and 2 `integrate` runs on INTEGRATED tasks; a reviewer could not give a review lock back. | Per-command `--help`; `hack-021` = `HACK-021`, and the refusal shows the value; the identity error gives the per-command `UAK_AGENT=NAME` prefix; finished tasks answer OK; `review ID --stop`. | `small_cli_fixes`, `rotation_skips_ghosts_and_asks_the_rejecter` |
| 13 | **"Queue busy" went to the human queue.** | `MERGE_BUSY`: wait and rerun; nothing reaches the humans. | `busy_queue_is_not_human` |
| 14 | **Codex notes.** The pre-commit hook was skipped for a missing executable bit; concurrent Verify and smoke overwrote one `q` log. | `doctor` checks (and `--fix` sets) `.githooks` executable bits; `q` writes one log per run. | — |
| 15 | **A 10-day sprint.** Nights are normal, and sprint defaults assume hours. | `uak clock` prints LONG EVENT advice for events of 24 h or more: adoption, `retire`, one digest per morning. | — |

## Still open
- Live checks still missing: the base64 rewrite in a real Windows Cursor session, and Codex's `updatedInput` in
  a live session. Both are tested against the documented payloads, and a failure is safe because the command
  just runs uncapped.
- "No identity" in the main checkout is not guessed: several agents share one git config there, so the kit asks
  for a per-command `UAK_AGENT=NAME` prefix.
- Agents glued words to numbers in 13 messages ("at8347f3d"). A detector caught more false positives than real
  cases on these 260 messages, so it stays a rule in AGENTS.md §5.3.
